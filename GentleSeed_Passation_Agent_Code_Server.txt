### Résumé exécutif

GentleSeed est une interface Web et un moteur d’aide à la sélection des releases multimédias. Il récupère les résultats de recherche de Radarr/Sonarr (dont les indexeurs sont généralement pilotés via Prowlarr), tient compte des refus/contraintes des applications *arr, classe les releases admissibles selon des préférences (qualité, langue, codec H.264/H.265, seeders), puis permet une sélection manuelle ou, à terme, automatisée. Le téléchargement et l’import restent pris en charge par Radarr/Sonarr et leur client configuré.

# GentleSeed — Dossier de passation technique et fonctionnelle

## 01 / Vision, périmètre et règles métier


### Finalité

Éviter le choix automatique de releases mal adaptées, sans réimplémenter les téléchargements ni contourner les exigences de Radarr/Sonarr. GentleSeed doit rendre le raisonnement de sélection visible, prévisible et contrôlable.

### Flux fonctionnel attendu

- 1. L’utilisateur sélectionne un média manquant (film, saison ou épisode) dans GentleSeed, ou un mécanisme automatique lui présente un nouveau média.
- 2. GentleSeed demande les informations et résultats de recherche à Radarr/Sonarr. Les indexeurs en amont sont configurés dans l’écosystème *arr, notamment via Prowlarr.
- 3. GentleSeed exploite les métadonnées de chaque release, les motifs de rejet signalés par *arr et les préférences de classement.
- 4. Il recommande une release admissible ou affiche « aucune release admissible » avec explications.
- 5. En mode manuel et avec confirmation explicite, l’utilisateur demande l’envoi de cette release à Radarr ou Sonarr.
- 6. Radarr/Sonarr transmettent eux-mêmes au client de téléchargement configuré (par exemple qBittorrent), et gèrent le suivi/import.
**Règle non négociable** — Jamais d’envoi direct vers qBittorrent depuis GentleSeed. L’application reste un sélecteur/orchestrateur : l’autorité de validation, l’envoi au client et l’importation des médias appartiennent à Radarr/Sonarr.


### Principes de classement

- Respecter d’abord les contraintes du profil *arr (qualité/cutoff, langue exigée, releases rejetées, minimum de seeders configuré, etc.).
- Classer ensuite les candidats admissibles selon la qualité souhaitée, la langue, les seeders et la préférence de codec H.264/H.265 (ou automatique).
- La préférence de codec doit être une pondération, pas une exclusion stricte de l’autre codec.
- Le choix manuel peut différer de la recommandation ; la raison et le mode de décision doivent apparaître dans les journaux.
- Ne pas implémenter les packs de films / collections : décision de périmètre explicite. Les packs de saison Sonarr sont un sujet distinct.

### Identité et préférences

- Direction visuelle Gentle Mates : rose/violet, cartes lisibles, logos Radarr/Sonarr, vues plus aérées ; thèmes clair, sombre et automatique, ainsi que variantes de couleur prévues.
- Authentification avec mot de passe choisi par l’utilisateur, sans mot de passe imposé ; exigence historique : même un mot de passe d’un caractère est accepté (conserver ce choix, signaler sa faiblesse de sécurité).
- Profil compact sans nom ; menu proposant Redémarrer, Arrêter, Se déconnecter.
- Langues multiples avec choix automatique ou manuel ; couverture fonctionnelle et qualité des traductions à contrôler lors de l’audit du code.
- Fuseau horaire détecté ou sélectionné ; format de l’heure 12 h / 24 h. Convention initiale suisse : JJ.MM.AAAA HH:mm:ss, fuseau Europe/Zurich (heure d’été/hiver).
- Conserver des timestamps techniques explicites avec fuseau, même si l’interface et les exports appliquent un format localisé.

## 06 / Incident ouvert : No Game No Life – Saison 00


### Symptôme reproduit sur l’interface v0.7.15

Parcours : Recherches → Sonarr – Épisodes / Saisons → Saison complète → No Game No Life – Saison 00 (8 épisodes manquants). Après lancement, l’interface affiche « Recherche non terminée » avec le message indiquant que Sonarr n’a pas répondu dans le délai prévu, puis propose « Réessayer ». Un délai API de l’ordre de 60 secondes a été observé dans la discussion précédente.
**Ce que ce message signifie / ne signifie pas** — Le timeout n’établit ni qu’il existe des releases ni qu’il n’en existe aucune. Une saison 00 regroupe des épisodes spéciaux, qui peuvent être nommés autrement ou distribués individuellement : une recherche par saison peut solliciter plusieurs recherches coûteuses.


### Hypothèses à distinguer

- Délai de réponse côté Sonarr/API, indexeur lent, requêtes successives ou attente excessive dans GentleSeed.
- Saison 00 moins bien couverte par les indexeurs ; titres/noms de releases atypiques ou épisode spécial introuvable.
- La recherche globale peut ne pas suivre le même chemin API qu’une recherche unitaire, ou gérer imparfaitement le timeout.
- Le libellé SIMULATION de l’UI peut créer une ambiguïté sur ce qui est réellement interrogé ; le clarifier si nécessaire.

### Diagnostic minimal sans déclencher de téléchargement

- Tester d’abord une saison ordinaire (S01+) avec épisodes manquants, puis un épisode isolé. Noter la durée, le nombre de résultats et le détail des refus.
- Reproduire la recherche de S00 en contrôlant les journaux Sonarr et GentleSeed ; examiner le temps pris par chaque étape et la réponse API exacte.
- Vérifier un S00E01 individuellement, puis un autre spécial. Comparer avec la recherche de saison et l’activité des indexeurs.
- Distinguer dans la réponse backend « 0 release trouvée », « toutes refusées », « erreur réseau/API » et « timeout ».
- Rendre le délai d’attente configurable et tracer les durées sans augmenter arbitrairement les timeouts pour masquer le blocage.
Critère de résolution : aucune recherche interrompue ne doit être présentée comme « aucun résultat ». Un timeout doit produire une erreur explicite et une trace exploitable, et les autres recherches doivent continuer à fonctionner.
